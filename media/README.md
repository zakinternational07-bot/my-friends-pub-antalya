# Медиа-кухня: исходники → .webp / .webm

Рабочая папка для подготовки картинок и видео к сайту. Сюда кладутся тяжёлые
исходники, отсюда забираются лёгкие файлы для `frontend/assets/...`.

```
media/
  source/     ← кладём сюда исходники (можно папками, структура сохранится)
  converted/  ← сюда скрипт складывает .webp / .webm
```

## Как пользоваться

```bash
node tools/convert-media.js
```

Скрипт проходит по всему, что лежит в `media/source/`, и складывает результат
в `media/converted/`:

- картинки (`.jpg`, `.png`, `.tif`, `.bmp`) → **`.webp`**, качество 82;
- видео (`.mp4`, `.mov`, `.avi`, `.mkv`) → **`.webm`**, VP9 (CRF 36) + Opus 128k.

Имена приводятся к веб-виду: `music saturday.PNG` → `music-saturday.webp`.

Повторный запуск не переделывает то, что уже сконвертировано (сравнивает даты
файлов), так что можно просто докидывать новые файлы в `source/` и запускать
снова.

### Ключи

| Ключ | Зачем |
|---|---|
| `--force` | переделать всё заново, даже уже сконвертированное |
| `--max-width 1600` | заодно уменьшить по ширине (маленькие не растягивает) |
| `--keep-names` | оставить исходные имена файлов как есть |
| `--crf 42` | сильнее сжать видео (больше число — меньше вес и хуже картинка) |
| `node tools/convert-media.js <вход> <выход>` | другие папки вместо `media/source` и `media/converted` |

### Если видео стало тяжелее исходника

Так бывает, когда исходник уже хорошо пожат (например, прислали через
мессенджер). Скрипт про это честно пишет в конце — тогда прогоняем ещё раз
с более сильным сжатием:

```bash
node tools/convert-media.js --force --crf 42
```

Картинок это почти не касается: фото и афиши в `.webp` стабильно легче.

## Требования

Нужен **ffmpeg** в системе:

```bash
winget install Gyan.FFmpeg
```

## Важно про git

Содержимое `media/source/` и `media/converted/` в репозиторий не попадает
(см. `.gitignore`) — это рабочие файлы. В git идут только те файлы, которые
осознанно перенесены в `frontend/assets/...` для использования на сайте.
