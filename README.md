# My Friends Pub — Antalya

Сайт филиала паба в Анталии: фронтенд на чистом HTML/CSS/JS + backend на
Node.js/Express с SQLite, бронированием мест и оплатой в **тестовом режиме**.

## Быстрый старт

```bash
cd backend
npm install
cp .env.example .env
# открой .env и задай ADMIN_USERNAME / ADMIN_PASSWORD / SESSION_SECRET
npm run dev
```

Сервер поднимется на `http://localhost:3000` и отдаёт и API, и фронтенд.
Открой `http://localhost:3000/` — попадёшь на главную страницу.
Админка: `http://localhost:3000/html/admin/login.html`
(логин/пароль — те, что задал в `.env`).

При первом запуске автоматически создаётся `backend/data/mfp.sqlite` и
сидируются: админ-аккаунт, план зала (7 столов/зон), 3 примера мероприятий
на ближайшую неделю и пример меню на 3 языках — чтобы сайт не был пустым
"из коробки". Отредактируй/удали через админку.

## Что уже по-настоящему работает

- Бронирование мест с временным холдом (10 минут по умолчанию,
  `SEAT_HOLD_MINUTES` в `.env`) и защитой от двойного бронирования одного
  места на уровне транзакции БД.
- Живое обновление занятости мест между вкладками/устройствами через
  WebSocket (`/ws`), с поллингом раз в 15 сек как фолбэком.
- Генерация билета с QR-кодом и номером брони.
- **Подтверждение брони на бесплатные мероприятия через Telegram** —
  вместо оплаты (см. раздел ниже). Полностью настоящая интеграция,
  протестирована с реальным ботом и живым вебхуком.
- Админ-панель: мероприятия (заголовок, описание, дата/время, цена, одна
  зона загрузки фото ИЛИ видео — файл реально загружается и сразу
  показывается на сайте), меню на 3 языках (категории + пункты), план
  зала (JSON-редактор), просмотр всех броней.

## Что работает в тестовом режиме (без реальных денег/писем)

- **Оплата** — `backend/src/services/payment/MockPaymentProvider.js`.
  Подключение реального шлюза:
  1. Создать `backend/src/services/payment/IyzicoProvider.js` (или
     `PayTRProvider.js`), реализующий тот же интерфейс, что
     `PaymentProvider.js` (`createPayment`, `confirmPayment`).
  2. Добавить ветку в `backend/src/services/payment/index.js`.
  3. В `.env`: `PAYMENT_PROVIDER=iyzico` + API-ключи шлюза.
  4. Понадобится: юрлицо/ИП в Турции для приёма платежей, договор с
     эквайером, API-ключи из личного кабинета шлюза.
- **Письма с билетом** — `backend/src/services/email/ConsoleEmailService.js`
  логирует и сохраняет письмо в `backend/data/emails/*.html`, реально не
  отправляет. Подключение Resend/SendGrid — аналогично оплате, через
  `backend/src/services/email/index.js` и `EMAIL_PROVIDER` в `.env`.
  Понадобится: аккаунт в сервисе рассылки + API-ключ + подтверждённый
  домен отправителя.

## Telegram-подтверждение брони на бесплатные мероприятия

Для мероприятий с ценой 0 (`event.price === 0`) кнопка «Оплатить билеты»
на `booking.html` заменяется на «Подтвердить бронь в Telegram». Флоу:

1. Гость заполняет имя/email, выбирает места, жмёт кнопку — создаётся
   обычная held-бронь (10 минут на подтверждение, как и везде), но вместо
   `payment.html` гостя переносит в `t.me/<бот>?start=<токен>`.
2. Гость жмёт «Start» в Telegram → бот получает это через вебхук
   (`POST /api/telegram/webhook`), находит бронь по токену, помечает
   `status = 'paid'` (место занято) и шлёт гостю подтверждение с деталями
   брони.
3. Раз в 10 минут (`backend/src/services/reminderScheduler.js`) сервер
   проверяет: если до мероприятия осталось ≤ `REMINDER_HOURS_BEFORE`
   часов (по умолчанию 6) и напоминание ещё не отправлено — шлёт
   сообщение с двумя кнопками-**ссылками** «✅ Подтверждаю» / «❌ Не смогу
   прийти», ведущими на `/rsvp/<бронь>/confirm` и `.../decline` на этом
   же сайте.
4. Открытие любой из этих ссылок — само по себе действие (не нужен
   отдельный клик на сайте): сразу меняет `attendance_status`, а при
   отмене ещё и освобождает место (`status = 'cancelled'`, место сразу
   пропадает из занятых для всех остальных) и шлёт уведомление в
   `TELEGRAM_STAFF_CHAT_ID`, если он задан.

Никакого отдельного бота с обработкой нажатий не нужно — кнопки-ссылки
просто открывают URL, вся логика подтверждения живёт на уже
существующем сервере (два новых роута: `telegramWebhook.js` и `rsvp.js`).

### Настройка

В `.env` (или в переменных окружения Render — уже прописаны в
`render.yaml`, кроме секретных):

```
TELEGRAM_BOT_TOKEN=...       # от @BotFather, секрет
TELEGRAM_BOT_USERNAME=...    # без @
TELEGRAM_STAFF_CHAT_ID=      # необязательно — куда слать уведомления об отменах
REMINDER_HOURS_BEFORE=6
PUBLIC_BASE_URL=...          # на Render не нужен — берётся из RENDER_EXTERNAL_URL сам
```

При старте сервер сам регистрирует вебхук в Telegram (`setWebhook`), если
`TELEGRAM_BOT_TOKEN` и публичный адрес заданы — вручную ничего вызывать
не нужно, просто передеплой на Render с настроенными переменными.

**Важно про Render free tier:** планировщик напоминаний — это обычный
`setInterval` внутри процесса, а не отдельный Cron Job. Пока сервис
"спит" от бездействия (см. раздел про хостинг ниже), напоминания не
отправляются — уйдут с опозданием, когда кто-то в следующий раз
разбудит сайт заходом на него. Для реальной эксплуатации без сюрпризов
стоит либо перейти на платный тариф (сервис не спит), либо завести
отдельный Render Cron Job, который раз в N минут дёргает публичный
эндпоинт (можно добавить по запросу).

## Хостинг

Код лежит на GitHub: https://github.com/zakinternational07-bot/my-friends-pub-antalya
(приватный репозиторий).

### Демо/прототип — Render (бесплатно)

В репозитории есть `render.yaml` — Render подхватит его сам и настроит
почти всё автоматически:

1. Зарегистрироваться на https://render.com (можно через GitHub-аккаунт).
2. New → Blueprint → выбрать репозиторий `my-friends-pub-antalya`.
3. Render найдёт `render.yaml` и предложит создать сервис `my-friends-pub-antalya`.
   Единственное, что попросит ввести вручную — `ADMIN_PASSWORD` (пароль
   от админки). Остальные переменные окружения уже прописаны в blueprint
   (`SESSION_SECRET` сгенерируется сам, `PAYMENT_PROVIDER=mock`,
   `EMAIL_PROVIDER=console` и т.д. — тестовый режим).
4. Deploy — через несколько минут сайт будет доступен по адресу вида
   `https://my-friends-pub-antalya.onrender.com`.

Особенности бесплатного тарифа Render: сервис "засыпает" после ~15 минут
без запросов и просыпается ~30-50 секунд на первый запрос после этого —
нормально для демо, неприемлемо для реального продакшена. Диск
эфемерный: `backend/data/mfp.sqlite` (и тестовые брони/данные в ней) не
переживёт передеплой или долгий сон — но `seed.js` автоматически заново
засеет демо-данные (мероприятия, меню, план зала) при пустой БД, так что
сайт всегда "просыпается" в рабочем виде.

**Важно:** по той же причине (эфемерный диск) фото/видео, загруженные
через админку в мероприятия (`backend/src/middleware/upload.js`,
сохраняются в `frontend/assets/images/events/` и `.../video/events/`),
тоже пропадут при передеплое или долгом простое — вместе с самим
мероприятием, если БД тоже сбросилась. Для демо это не проблема
(добавил мероприятие с фото — показал — не страшно, если потом
исчезнет), но для реальной эксплуатации нужен постоянный диск
(платный тариф) или загрузка в облачное хранилище (S3/Cloudinary и т.п.
вместо локального диска).

### Продакшен (когда сайт станет боевым, не демо)

- **Простой**: один VPS (например, обычный хостинг с Node.js) — Express
  раздаёт и API, и статику фронтенда, как сейчас локально.
- **Раздельный**: фронтенд на Vercel/Netlify (статика из `frontend/`),
  backend на Railway/Render на платном тарифе с постоянным диском
  (нужен постоянно работающий процесс из-за WebSocket и SQLite-файла —
  либо перейти на управляемую БД, например Postgres через Supabase —
  схема в `backend/src/db/schema.sql` переносится почти без изменений).

В обоих случаях: включить HTTPS, сгенерировать длинный случайный
`SESSION_SECRET`, сменить `ADMIN_PASSWORD` на надёжный, подключить
реальный платёжный шлюз и почтовый сервис (см. выше).

## Структура проекта

```
frontend/   html/ css/ js/ assets/ — статические файлы сайта
backend/    server.js + src/{db,routes,services,ws,middleware}
```

Подробности по конкретным решениям (модель данных, флоу бронирования) —
в комментариях внутри `backend/src/db/schema.sql` и
`backend/src/services/seatHold.js`.
