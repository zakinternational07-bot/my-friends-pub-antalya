# Техническое задание: сайт My Friends Pub (Анталия)

## Контекст и цель

Нужен отдельный сайт для филиала паба в Анталии, независимый от сайта
петербургского филиала (myfriendspub.ru), которым мы не можем управлять
самостоятельно. Новый сайт должен позволять персоналу вносить правки
без привлечения сторонних разработчиков, а также автоматизировать
бронирование мест на мероприятия с онлайн-оплатой (сейчас брони
принимаются вручную через Telegram-группу, без предоплаты, из-за чего
часть гостей не приходит).

## Общие технические требования

- Не собирать всё в один HTML-файл. Разложить проект по нормальной
  структуре: отдельные папки `html/`, `css/`, `js/`, `assets/`
  (изображения, видео, шрифты).
- Использовать семантичный HTML5, CSS (можно с переменными для цветов/
  шрифтов, чтобы легко менять оформление) и JavaScript для интерактива.
- Адаптивная вёрстка (мобильные телефоны, планшеты, десктоп) — большинство
  гостей будут заходить с телефона по QR-коду со стола.
- Стилистика — как на текущем сайте myfriendspub.ru: тёмный фон
  (кирпичная стена/фото заведения), крупные жирные condensed-заголовки
  белым/красным цветом, красные плашки-акценты, минималистичные кнопки.
  Референс: https://www.myfriendspub.ru/page40857487.html

## Структура сайта

### 1. Главная страница

- Полноэкранная фотография интерьера паба на фоне.
- Поверх фото — три крупные кнопки по центру: **«Меню»**, **«Мероприятия»**,
  **«Другое»**.
- Логотип/название паба сверху.

### 2. Раздел «Меню»

- При нажатии — переход на отдельную HTML-страницу с меню.
- Переключатель из 3 языков (русский, английский, турецкий) — переключение
  на языки должно вести на отдельные HTML-страницы (menu-ru.html,
  menu-en.html, menu-tr.html или аналогично), а не менять текст через JS
  на одной странице.
- Пункт меню: название, описание (если есть), цена. Разбивка по
  категориям (закуски, горячее, напитки и т.д.).

### 3. Раздел «Мероприятия»

**3.1. Список мероприятий недели**
- Показывает афишу мероприятий текущей недели в виде карточек-колонок
  (по аналогии с печатной афишей паба — прикреплю фото для референса
  внешнего вида: дата, название мероприятия, фото, время, цена входа).

**3.2. Карточка мероприятия — детальная страница**
- При клике на карточку мероприятия открывается отдельная страница с:
  - расширенным описанием мероприятия;
  - встроенным видео с прошлых похожих мероприятий (видеоплеер);
  - кнопкой «Забронировать / Купить билет».

**3.3. Бронирование и рассадка**
- После нажатия «Забронировать» показывается схема зала: план столов
  и мест с указанием, какие уже заняты, а какие свободны.
- Гость выбирает нужное место (или несколько мест/весь стол, если
  бронирует компанией).
- После выбора появляется кнопка «Оплатить билеты».

**3.4. Оплата**
- Кнопка ведёт на страницу оплаты (нужен платёжный шлюз — уточнить,
  какой подключён/доступен в Турции, например iyzico, PayTR и т.п.).
- После успешной оплаты:
  - выбранные места помечаются как занятые и убираются из списка
    свободных для всех остальных гостей (обновление в реальном времени);
  - на почту, указанную при оплате, автоматически отправляется билет
    (например, PDF или письмо с QR-кодом/номером брони).

### 4. Раздел «Другое»

- Здесь опиши мне, что именно должно быть внутри (контакты, адрес,
  соцсети, история паба, что-то ещё) — это нужно уточнить отдельно
  перед тем, как передавать задание.

## Важный момент, который стоит сразу учитывать

Реальная система бронирования с оплатой и «живым» обновлением свободных
мест — это не просто статичный сайт из HTML/CSS/JS. Она требует:
- базы данных (хранение мест, броней, статусов оплаты);
- backend-сервера (обработка запросов, интеграция с платёжным шлюзом,
  отправка писем);
- защищённого приёма и подтверждения платежей.

Это стоит явно обозначить для Claude Code, чтобы он предложил
архитектуру (например: фронтенд на HTML/CSS/JS + backend на Node.js/
Express + база данных, к примеру Supabase/Firebase/PostgreSQL, +
почтовый сервис вроде Resend/SendGrid, + платёжный шлюз). Без этого он
может сделать красивый интерфейс, который не будет реально работать.

Помоги мне создать сайт для паба (My Friends Pub, филиал в Анталии,

https://www.myfriendspub.ru/page40857487.html (только оформление текста
и цветовую гамму, контент будет свой).

Структура:

1. Главная страница: фон — фото заведения на весь экран, поверх — три
   кнопки: «Меню», «Мероприятия», «Другое».

2. «Меню» — отдельная HTML-страница с меню, плюс переключение между
   тремя отдельными HTML-страницами меню на русском, английском и

   - страница со списком мероприятий на неделю в виде карточек (дата,

   - при клике по карточке — отдельная страница мероприятия с более

   - при нажатии на кнопку показывается схема зала со свободными и

4. «Другое» — [здесь опишу содержимое отдельно].

Учти, что бронирование с оплатой и обновлением занятости мест в реальном
времени требует backend и базы данных, а не только статичного
фронтенда — предложи подходящую архитектуру (backend, БД, интеграцию с
платёжным шлюзом и отправкой писем) и объясни, что для этого понадобится
на моей стороне (хостинг, ключи API и т.д.).
